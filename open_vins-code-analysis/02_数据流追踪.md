
## 4. 其他传感器数据流

本仓库主线为 **视觉 + IMU** 双传感器，无其他传感器（无 GPS/激光/轮速计）接入 pipeline。
- **Aruco 标签**：非独立传感器，复用相机图像，在跟踪阶段由 `trackARUCO` 并行检测，提供绝对/半绝对约束（经 `UpdaterSLAM` 作为 SLAM 特征加入）。
- **真值 (GT)**：仅在 `ov_data/` 数据集文件与 `live_align_trajectory` / `pose_to_file` 评估节点中使用，不参与在线估计。

## 5. 核心数据结构定义

### 5.1 帧/图像测量 —— `CameraData`
```cpp
// ov_core/src/utils/sensor_data.h
struct CameraData {
  double timestamp;                 // 时间戳
  std::vector<int> sensor_ids;      // 各图像对应的相机id (stereo=[0,1])
  std::vector<cv::Mat> images;      // 每相机一帧灰度图
  std::vector<cv::Mat> masks;       // 每相机跟踪掩码 (ROI)
  // operator< 按 timestamp+camid 排序 → 支撑 camera_queue 有序
};
```

### 5.2 IMU 测量 —— `ImuData`
```cpp
// ov_core/src/utils/sensor_data.h
struct ImuData {
  double timestamp;                 // 时间戳
  Eigen::Vector3d wm;               // 角速度 (rad/s)
  Eigen::Vector3d am;               // 线加速度 (m/s^2)
};
```

### 5.3 特征点 —— `Feature`
```cpp
// ov_core/src/feat/Feature.h:39
class Feature {
  size_t featid;                    // 唯一特征id
  std::unordered_map<size_t, std::vector<Eigen::VectorXf>> uvs;        // 各相机id下的像素观测
  std::unordered_map<size_t, std::vector<Eigen::VectorXf>> uvs_norm;   // 归一化观测
  std::unordered_map<size_t, std::vector<double>> timestamps;          // 各观测的时间戳
  int anchor_cam_id;                // 锚定相机id
  double anchor_clone_timestamp;    // 锚定 clone 时间
  Eigen::Vector3d p_FinA;           // 锚定系下的三角化位置
  Eigen::Vector3d p_FinG;           // 全局系下的三角化位置
};
```
> 由 `FeatureDatabase`（`ov_core/src/feat/FeatureDatabase.h:54`，带 `std::mutex mtx` 线程安全）统一管理，按 id 索引，并提供 `features_not_containing_newer` / `features_containing` 等查询，供 VioManager 选取"丢失/待边缘化/SLAM"特征集。

### 5.4 滤波器状态 —— `State` (ov_msckf)
```cpp
// ov_msckf/src/state/State.h
class State {
  std::shared_ptr<IMU> _imu;              // 当前 IMU 状态 (位姿/速度/bias)
  std::map<double, PoseJPL> _clones_IMU;  // 滑动窗口: 历史 IMU clone (时间戳→位姿)
  std::unordered_map<size_t, std::shared_ptr<Landmark>> _features_SLAM; // 活跃 SLAM 地图点
  // 标定量: _calib_dt_CAMtoIMU, _calib_imu_dw/da/tg, 相机内参/外参 ...
  double _timestamp;                      // 当前状态时间
  double margtimestep();                 // 最早 clone 时间 (边缘化边界)
};
```
> 误差状态 EKF：每个 `Type`（`ov_core/src/types/`）持有误差状态及其雅可比；`StateHelper`（`ov_msckf/src/state/StateHelper`）负责克隆增广、边缘化、SLAM 特征增删。

## 6. 线程间通信方式

> **修正 Phase 1 结论**：本仓库**并非纯单线程**。ROS1 用 `AsyncSpinner(0)`（全 CPU 线程）接收回调；IMU 回调中会 **spawn 一个 worker 线程**（默认 `use_multi_threading_subs=true` 时 `detach`）来 drain 相机队列；另有可选的发布线程（`use_multi_threading_pubs`）。因此并发点为"ROS 回调线程 ↔ 相机处理 worker 线程"通过共享队列 + mutex 通信。

| 数据名称 | 发送方模块 | 接收方模块 | 通信机制 | 缓冲区/队列 | 同步方式 |
|---------|-----------|-----------|---------|------------|---------|
| `CameraData` (图像) | ROS 回调线程 | 相机处理 worker 线程 | `camera_queue` (`std::deque`，按时间戳排序) | 无显式上限（受 IMU 节奏 drain） | mutext `camera_queue_mtx` (`ROS1Visualizer.cpp:586`) |
| `ImuData` (IMU) | ROS 回调线程 | `Propagator` / `InertialInitializer` / `UpdaterZUPT` | 成员缓冲 `imu_data` | 受 `oldest_time` 裁剪 | mutex `imu_data_mtx` (`Propagator.cpp:67`) |
| `Feature` 观测 | `TrackKLT` | `FeatureDatabase` | 共享对象 | - | mutex `mtx` (`FeatureDatabase`) + 每相机 `mtx_feeds` (`TrackBase.h:174`) |
| 处理结果 (位姿) | `VioManager` | `ROS*Visualizer::publish_state` | ROS publish `/ov_msckf/poseimu` | - | ROS 中间件 |
| 可视化图像/特征 | `Viz` 内部 | 发布线程 (可选) | 函数调用 / 共享 state | - | mutex（若 `use_multi_threading_pubs`） |
