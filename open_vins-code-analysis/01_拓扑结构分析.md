## 4. 构建系统分析

### 4.1 编译目标

**ov_msckf（主库 + 可执行文件）** — 定义在 `ov_msckf/cmake/ROS1.cmake` / `ROS2.cmake`：

| 目标名 | 类型 | 源文件 | 说明 |
|--------|------|--------|------|
| `ov_msckf_lib` | 共享库 | `src/*.cpp` + 递归包含 `ov_core/src/*.cpp` + `ov_init/src/*.cpp` | 核心库（把 core/init 一并编入） |
| `ros1_serial_msckf` | 可执行 | `src/ros1_serial_msckf.cpp` | ROS1 节点（bag/串口直读，主入口之一） |
| `run_subscribe_msckf` | 可执行 | `src/run_subscribe_msckf.cpp` | ROS 订阅节点（主入口之一） |
| `run_simulation` | 可执行 | `src/run_simulation.cpp` | 脱离 ROS 的纯仿真入口 |
| `test_sim_meas` / `test_sim_repeat` | 可执行 | 对应 test 源 | 仿真一致性测试 |

> ROS2 构建仅产出 `run_subscribe_msckf` / `run_simulation` / `test_sim_meas` / `test_sim_repeat`（无 serial 变体，serial 为 ROS1 专用）。

**ov_core 可执行（测试）**：`test_webcam`, `test_tracking`, `test_profile`
**ov_init 可执行（测试）**：`test_simulation`, `test_dynamic_init`, `test_dynamic_mle`
**ov_eval 可执行（工具，11 个）**：`error_comparison`, `timing_comparison`, `plot_trajectories`, `format_converter`, `live_align_trajectory`, `error_dataset`, `timing_flamegraph`, `pose_to_file`, `error_singlerun`, `error_simulation`, `timing_histogram`, `timing_percentages`

### 4.2 子模块划分

```
ov_msckf_lib (SHARED)
├── ov_msckf/src/*.cpp          → 估计器主体
├── ov_core/src/*.cpp (GLOB)    → 核心库 (相机/IMU/特征/跟踪/类型)
└── ov_init/src/*.cpp (GLOB)    → 初始化模块
```
> 注意：`ov_msckf_lib` 通过 `file(GLOB_RECURSE ...)` 把 `ov_core` 与 `ov_init` 源码一并编入，因此运行时这两个模块以"源码并入"方式集成，而非独立动态库链接。

### 4.3 ROS 工程额外信息

- **package names**: `ov_core`, `ov_data`, `ov_init`, `ov_msckf`, `ov_eval`（`ov_data` 仅含数据，无节点）
- **依赖的 ROS 包（ov_msckf）**: `roscpp`（ROS1）/ `rclcpp`（ROS2）、`cv_bridge`、`sensor_msgs`、`geometry_msgs`
- **Launch 文件**:
  - `ov_msckf/launch/subscribe.launch`：启动 `run_subscribe_msckf` 主节点 + 可选 `rosbag play` + `pose_to_file` 记录 `/ov_msckf/poseimu`
  - `ov_msckf/launch/serial.launch`：启动 `ros1_serial_msckf` 主节点（ROS1 专用）
  - `ov_msckf/launch/simulation.launch`：纯仿真
  - `ov_init/launch/mle.launch`, `dynamic.launch`：初始化相关
  - `ov_eval/launch/record.launch`：评估记录
- **关键话题（来自 `ros/` 层默认参数）**:
  - 相机图像：`/cam{i}/image_raw`（可被 `topic_camera{i}` 参数覆盖）
  - IMU：由 Subscriber 配置（默认 `/imu0`）
  - 输出位姿：`/ov_msckf/poseimu`（PoseWithCovarianceStamped）

### 启动流程简述（以 `run_subscribe_msckf` 为例）

```
main()  →  ros::init / rclcpp::init
  ├── 1. 读取 config_path 与参数 (verbosity, use_stereo, max_cameras...)
  ├── 2. 构建 VioManager (载入 ov_core 类型/相机/特征库、ov_init 初始化器)
  ├── 3. 注册 ROS 订阅回调 (图像 / IMU)
  │       图像/IMU 到达 → 缓存到 FeatureDatabase / 时间对齐缓冲
  ├── 4. 启动 Viz (ROS1/ROS2 Visualizer)，订阅结果话题以可视化
  └── 5. ros::spin() 事件循环
       └── 回调触发 → VioManager->feed_measurement_*/track_image_*
            → Propagator 传播 → 初始化 → Updater* 更新 → 发布 /ov_msckf/poseimu
```

## 6. 线程 / 节点模型

| 线程/节点 ID | 创建位置 | 职责 | 运行方式 |
|-------------|---------|------|---------|
| ROS 主线程 (spin) | `run_subscribe_msckf.cpp:56/65` | 接收图像/IMU 回调，驱动 VioManager | 事件驱动（单线程 spin） |
| （可选）bag 播放节点 | `subscribe.launch` | 回放 rosbag 提供数据 | 独立 ROS 节点 |
| `pose_to_file` 节点 | `subscribe.launch` | 订阅 `/ov_msckf/poseimu` 落盘 | 独立 ROS 节点 |
| `live_align_trajectory` 节点 | `subscribe.launch` | 实时对齐真值可视化 | 独立 ROS 节点 |

### 线程间通信

| 数据 | 发送方 | 接收方 | 通信机制 | 同步方式 |
|------|--------|--------|---------|---------|
| 图像帧 | ROS 回调 | `TrackBase` / FeatureDatabase | ROS 回调参数 / 内部缓冲 | `std::mutex mtx_feeds[]`（每相机一锁）+ `mtx_last_vars` |
| 特征 / 地图点 | 跟踪器 | `FeatureDatabase` | 共享对象 | `std::mutex mtx`（FeatureDatabase 内） |
| 测量结果 | 回调/仿真 | `VioManager` | 函数调用（同一线程） | 无（单线程顺序执行） |
| 位姿输出 | `VioManager` | `Visualizer` → 话题 | ROS publish | ROS 中间件 |

> **关键发现**：全仓**未显式创建 `std::thread` / `pthread` 工作线程**（grep `std::thread|std::async|pthread_create` 无结果）。并发仅通过 ROS 单线程 spin 的事件回调串联，各模块内部用 `std::mutex`/`lock_guard` 保护共享缓冲（主要是特征库与跟踪器_last 变量）。即：**单线程的事件驱动模型**，mutex 用于回调间共享数据的安全访问，而非并行计算。
